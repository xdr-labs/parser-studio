# Source Grammar Trust Registry — Isolated PoC (2026-10-17)

## Why this exists

A parser must not elevate a candidate to independently verified merely because
its own code, or a caller, supplies an `independent_source_oracle` label. The
previous source-fidelity component checks caller-supplied field values against
candidate values, but the caller could have generated both. That is useful as a
low-level consistency check, **not** a reviewed reference source.

This unit adds a repository-controlled *pinned lexical-reference registry* to
avoid trusting arbitrary fixture IDs, caller-generated expected fields, or
self-claimed source provenance. This is a **PoC diagnostic** and remains
isolated from the current product parser and export path.

## Architecture and exact trust boundary

- `src/poc/sourceTrustPins.json` records immutable event SHA-256, the
  independently tokenized **ordered** field/value digest, unparsed-prefix
  digest, original field count, and repeated field count. These are checksums
  and source identifiers **only**. No raw source event or values are committed.
- Eight entries originate from the previously pinned, published Elastic
  Integrations SonicWall sources at upstream revision
  `ee918d03f4a90dacd32673546c64a633308796ef`. They were generated by a
  separate Python lexical oracle and remain explicitly
  `INDEPENDENT_LEXICAL_UNREVIEWED`, not approved source semantics.
- The ninth entry is a synthetic source fixture, clearly labeled
  `SYNTHETIC_CONTROL_ONLY`, used for deterministic CI tests without requiring
  private source records.
- `src/poc/sourceTrustRegistry.ts` accepts **only** a fixture ID and bounded
  candidate. A caller may **not** pass a replacement approved registry or
  expected field values. The pinned ID, grammar, exact original source bytes,
  prefix, key/value order, duplicate count, and first/second pass replay must
  all match.
- `PINNED_LEXICAL_MATCH_UNREVIEWED` means *only* that source fields match
  repository-pinned independent lexical output; it is not an approval of
  vendor grammar provenance, semantic field names, normalization, target
  dictionary, native Parser Studio execution, parser export, or deployment.
  Returned `sourceGrammarApproved`, `semanticMappingApproved`,
  `nativeRuntimeApproved`, `productPromotionAllowed` are **always false**,
  and `requiresIndependentReview` is always true.

The pin manifest is source-controlled so any later modification is reviewable
through Git history and PR diff. Source-controlled hashes are not a signature
or a cryptographic assertion that a human/vendor approved the grammar.
Stronger real-world trust establishment would require external reviewed
source documentation or signed reference provenance **outside** the parser
runtime and a separate human reviewer.

## Measured, bounded source evidence

The pinned 265-event development/evaluation corpus was already used to
develop the common tokenizer. Its additional eight SonicWall prefixed-KV
records remain **Partial**, not full structural successes.

| Gate | Result |
| --- | ---: |
| Public independent lexical pin entries | 8 |
| Synthetic regression control entries | 1 |
| Pinned public source events with exact ordered fields | **8/8** |
| Pinned public source raw/prefix identities retained | **8/8** |
| Modified source records correctly rejected | **8/8** |
| Product parser promotions | **0** |
| Human-approved vendor grammar entries | **0** |
| Normalization / native compatibility verified | **0** |

These figures do not extend the original 535/571 or 229/265 structural
success counts; source field correctness is separate from structural
acceptance, semantic mapping, and native parser compatibility. The 222
additional unseen public events from the preceding PoC had **no independently
scannable complete lexical source KV references**, so their field fidelity
remains **NOT SCORABLE**, not 100% by vacuous truth.

## Reproduction

From the separately isolated worktree:

```sh
python3 scripts/poc/fetchLosslessGrammarCorpus.py
python3 scripts/poc/createLosslessIndependentOracle.py --split development
python3 scripts/poc/createSourceTrustPins.py
npx vite-node scripts/poc/runPinnedSourceTrustOracle.ts
npx vitest run src/poc/sourceTrustRegistry.poc.test.ts
npm test
npm run typecheck
npm run build
```

The original source files and decoded oracle data remain restricted to
`~/.local/state/parserstudio-lossless-fresh-20261017/` with mode 0700 on
the directory and 0600 on files. This repository contains pin hashes only.

The test suite explicitly checks unknown fixture identities, forged original
content, misordered/replaced/lost source fields, unexpected grammar,
unapproved provenance, and private source mutation. An absent independent
reference must produce `NOT_ENROLLED`, not `VERIFIED`.

## Next acceptance stage

1. Define an independently reviewed source-grammar ownership contract with
   real documentation-backed reviewer identity, version, approved
   event-family scope and field semantics. Do **not** mark the eight
   automatically extracted lexical references as human approved.
2. Separate Stellar source field extraction (string offsets/value) from
   Dictionary-backed target mapping (types, aliases, collisions, nulls).
3. Require independently measured field precision/recall on a newly
   collected, non-tuned dataset, including useful abstentions.
4. After source grammar and semantic mapping gates pass, introduce an
   opt-in integration seam to the bounded existing Multi-Pass Funnel and
   verify browser, real HTTP/backend, and authorized native target
   execution at a single exact HEAD.

No production, product merge, DP upload, sensor, release, or native
compatibility claim is included here.
