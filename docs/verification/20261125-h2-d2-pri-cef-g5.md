## H-2: lossless ChatGPT recovery of multi-token residual regions

Multi-Pass reports, per event, the UTF-8 byte ranges it could not read. For a regex candidate (a standalone regex
or a Syslog body regex) the browser runs the same portable expression with match indices and gets the exact byte
span of every named capture. Rules:

- A value-bearing character of a residual region must lie inside a capture whose text reaches the final output.
  Value-bearing: letters, digits, marks, `_`, non-ASCII; a `-` before a digit or a decimal point, or after a
  non-word character before a word or another `-` (`-inf`, `"-inf"`, `--verbose`, not `src-ip`); every `+`; a `.` next to a digit; a `:` between digits or in `::`; a `%` next to a digit; `=` in `!=`,
  `<=`, `>=`, `==`; other punctuation except the separators `/ | , ; " ' [ ] ( ) { } @ ? & \`.
- A key may stay literal before `=` (blanks around `=` and one opening quote or bracket, inside or outside the
  capture, allowed) only with a capture spelled exactly like the key.
- A capture inside a repetition is refused (only its last iteration would be kept).
- Each capture must prove its own value (field identity). The holders are the output fields that hold exactly the
  capture text. One character of the capture is changed in the event and the candidate runs on the changed event:
  the capture is carried when a holder then holds the changed text, and not carried when no holder changes. A
  holder that changes another way (a cast that refuses the changed text) decides nothing; when no probe decides
  (fixed alternatives, punctuation), the capture is renamed in the expression and must still make a holder change.
  With event profiles a rename can change the route, so such a capture is refused. A twin copy, a capture mapped
  twice or a cast that rewrites the text (`0443` to 443) cannot pay for a dropped value.
- Multi-Pass ranges are relative to its frame (after a UTF-8 BOM and leading blanks); they are shifted onto the
  browser event. A regex candidate whose evidence is missing (ranges that do not fit, worker failure or time-out,
  no match) is refused. The substring whole-value rule is used only for non-regex candidates, as before.

## G-5

A source field named `__proto__`, `constructor` or `prototype` is kept as `parserstudio_key_<name>`; a name that
already starts with `parserstudio_key_` gets the prefix again, so the mapping is injective and reversible
(`originalFieldName`). Dotted keys are kept. No prototype pollution in any engine (KV, JSON, CEF, LEEF). Chromium
down to Ruby 2.4.9: KV 3 units, 3 records, 0 problems; JSON 3 units, 3 records, 0 problems (`a.b` kept in
`parserstudio_unmapped`, nested `a.b` kept as an object). Acceptance of these names by Stellar Cyber/Fluentd DP
indexing is the owner's test (NOT VERIFIED here).
