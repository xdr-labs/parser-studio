# Independent Oracle H3 — deterministic event-order metamorphic regression

Status: **H3 first increment**. This is not full semantic acceptance for every
security-source grammar or proof of Stellar Cyber DP compatibility.

`src/guided/mappingMetamorphicOracle20261107.test.ts` exercises
100 fixed-seed synthetic combinations containing 2–10 event types, each with
fewer than 100 individually safe source leaf fields. Independent expected
official fields are `srcip`, `dstip`, `srcport`, `dstport` and `proto`.

Each seed generates forward, reversed, rotated and seeded-shuffled event orders
and checks the same source/target/type/observed-count proposal set. All five
official fields must remain human-review candidates rather than being
silently auto-promoted when present in only one event type. Unicode values in
vendor-only fields remain byte-identical, and intentionally competing source
aliases for one official destination must remain ambiguous in both orders.

The oracle is **separately authored**: target expectations are fixed in the
test and are not copied from Parser Studio output. The seeds and fixture text
are static, reproducible and contain no customer data.

Remaining H3 coverage: independently sourced positive/negative fixtures for
each supported grammar, UTF-8 byte offset accounting, numeric/NULL/boundary
mutations, complete generated Ruby field/error parity and real user browser
scenarios. Do not claim a vendor-wide accuracy percentage from these synthetic
metamorphic tests.

## H3 independently authored eight-grammar native goldens (stacked Draft)

The next CI Native oracle increment adds 16 fixed positive/negative
**synthetic** source records over eight supported ParserProject extraction
grammars: JSON, KV, CSV, CEF 0, LEEF 2.0, RFC 5424 with KV body, RFC 3164
with KV body and reviewed bounded named-capture Regex.

Each grammar fixture has separately authored input text, expected official
`srcip` and `action`, expected event index, and a deliberately invalid IP
variant. The latter must produce a `normalization`-stage
`MappedFieldError`, identify the exact offending field, retain the
independently valid action and exclude the invalid official `srcip` without
echoing source text. Multiple structured fixtures contain original Korean
Unicode values; source identity is preserved by SHA-256 and UTF-8 byte count.
The native test generates the real Ruby parser from each validated DRAFT
project and executes it with the fixture pair in Ruby CI.

This is an additional independently specified, small synthetic
grammar-coverage gate, **not** real-manufacturer accuracy evidence, not
grammar-complete matched/unmatched byte accounting and not Stellar DP 7.0
qualification. The remaining H3 target requires larger independent
manufacturer-sourced positive/negative corpora, protocol-specific
holdouts, matched/residual offset goldens and repeated browser/Native
differential runs without reusing implementation-produced expected output.

## H3 six-grammar, UTF-8 source-byte independent truth increment (2026-11-08)

`tests/test_h3_independent_six_family_bytes_20261108.py` supplies
**independently authored source text and expected literal value spans** for
KV, JSON, CEF, LEEF, RFC 3164 and RFC 5424. It compares original UTF-8
SHA-256, length and every expected field's byte range against the parser's
output, including explicit JSON string quotes. Eight multilingual source
values (Hangul, Japanese, emoji with modifiers/ZWJ, Greek, Arabic and Thai)
cover three source-order permutations per six-family mixed batch.
The test checks all event boundaries, newline framing bytes, per-event hashes,
residual lists, exact label ownership and boundaries within UTF-8 codepoints.
No expected value, byte position or classification is generated by the parser.

Negative source evidence deliberately distinguishes three outcomes:
JSON repeated property names must not be accepted as an unambiguous object,
CEF duplicate extensions are explicit review cases, while valid lexical KV
repetitions preserve **both** observed values as an array. The latter is
not an official scalar mapping candidate. The browser regression
`h3DuplicateKvMappingGuard20261108.test.ts` locks down the no-normalization
fail-closed path and exclusion of arrays from eligible field suggestions.
This work does **not** relabel syntactically parsed KV arrays as malformed or
erase original duplicate values.

This is a source engine/browser evidence increment only. Existing generated
Ruby independent goldens and H2 CI isolation are separate evidence; a
same-source native differential test across **all** supported families and
Stellar Cyber DP 7.0 import/receive qualification are not completed by it.

## H3 publisher-attributed original-source excerpts (2026-11-08)

The fixed H3 holdout in
`tests/test_h3_official_vendor_source_excerpts_20261108.py` adds **two
publisher-attributed, contiguous excerpts** from official manufacturer log
documentation. They are deliberately **not** presented as entire vendor logs
or customer-production evidence.

- **Fortinet FortiOS Traffic** — [Log message fields, FortiOS 7.4.2](https://docs.fortinet.com/document/fortigate/7.4.2/fortios-log-message-reference/357866/log-message-fields).
  The first 16 raw KV fields from the published 2017 traffic example are
  preserved verbatim; the later action field was not copied. Independent truth
  asserts source/destination IP, source/destination port **as source strings**,
  original byte spans and source hash. No invented action mapping is allowed.
- **WatchGuard Firebox Traffic Monitor** —
  [Read a Log Message](https://www.watchguard.com/help/docs/help-center/en-us/content/en-US/Fireware/logging/read_log-msg.html).
  A contiguous excerpt of the 2024 Member2 Allow example retains the
  original source/destination IP positional tokens and trailing `proc_id`
  and `rc` indicators. The currently supported local source parser keeps
  those addresses as unmatched/partially recovered positional evidence and
  does **not** assign official `srcip`/`dstip` semantics without explicit
  positional-grammar review. This is **not** scored as normalized success.

For both excerpts, the oracle asserts the original UTF-8 source hash,
physical input identity, source-bound byte spans and no Native/target claim.
Reversing the two records in a batch must preserve both per-event source
bytes and newline framing. Test scope: three Python unit tests, fixed public
source excerpts only. The complete manufacturer logs are not reproduced,
and production receiver/DP 7.0 import is untested.

This is independent publicly documented format *evidence*, not a claim of
full production vendor normalization accuracy. Expand future holdouts only
with license-safe verified source artifacts, explicit sample provenance and
independently authored expected output; do not invent samples to improve
an accuracy score.
